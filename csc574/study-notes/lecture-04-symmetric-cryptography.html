Learning objectives

By the end of this lecture, you should be able to:

  • Distinguish stream ciphers from block ciphers.
  • Explain why stream-cipher reuse and IV reuse are catastrophic.
  • Describe the high-level structure of modern block ciphers.
  • Explain ECB, CBC, and CTR at a high level.
  • Identify major risks of confidentiality-only modes.
  • Choose between confidentiality-only and authenticated constructions for simple scenarios.

Not required: Derive AES internals by hand.

Answers

Distinguish stream ciphers from block ciphers

  • Stream cipher: generates a pseudorandom keystream from a key and additional state, then commonly XORs it with plaintext.
  • Block cipher: encrypts fixed-size plaintext blocks into fixed-size ciphertext blocks; a mode of operation handles longer messages.
  • Examples: RC4 is a historical stream cipher; DES, 3DES, and AES are block ciphers.

Explain why stream-cipher reuse and IV reuse are catastrophic

  • Reuse: encrypting two messages with the same keystream reveals $C_1 \oplus C_2 = M_1 \oplus M_2$.
  • IV or nonce: may be public, but it must not repeat with the same key because repetition can regenerate the same keystream.
  • WEP: its 24-bit IV repeated quickly, making RC4 keystream reuse practical to exploit.

Describe the high-level structure of modern block ciphers

  • Keyed permutation: a fixed key selects a reversible mapping over a fixed-size block space.
  • Rounds: repeated keyed transformations compose substitutions, permutations, and round-specific subkeys from a key schedule.
  • Confusion and diffusion: substitutions hide the key relationship; permutations spread input influence across output bits.

Explain ECB, CBC, and CTR at a high level

  • ECB: encrypts blocks independently and leaks repeated-block patterns.
  • CBC: XORs each plaintext block with the prior ciphertext block, using an IV for the first block.
  • CTR: encrypts unique nonce/counter values to create a keystream, then XORs it with plaintext or ciphertext.

Identify major risks of confidentiality-only modes

  • Pattern leakage: ECB retains visible structure in repeated plaintext blocks.
  • Malleability: CBC and CTR alone allow ciphertext manipulation without detecting it.
  • Operational rules: IV unpredictability and nonce uniqueness are part of the security argument.

Choose between confidentiality-only and authenticated constructions for simple scenarios

  • Authenticated encryption: prefer an approved AEAD mode in a vetted protocol whenever attackers can modify ciphertexts.
  • Confidentiality-only: use only when integrity and authenticity are provided elsewhere and the mode's IV or nonce rules are met.
  • Implementation: use vetted cryptographic libraries; do not roll your own cryptography.

Symmetric cryptography foundations

Symmetric cryptography uses the same shared secret key for encryption and decryption. It is generally fast and performant, but Alice and Bob must securely obtain and share that secret key.

Reusable-key approaches Slide 19

  • Stream cipher: extend a short reusable secret key into a much longer keystream, then combine that stream with the message.
  • Block cipher: split the message into fixed-size blocks, apply a key-based encryption operation to each block, and combine the encrypted blocks.

One-time pad recap Slide 13

A one-time pad uses a random bit sequence as long as the plaintext and combines it with the message using XOR. It offers perfect secrecy only when its key is random, secret, message length, and never reused.

C_1 \oplus C_2 = (M_1 \oplus K) \oplus (M_2 \oplus K) = M_1 \oplus M_2

Reusing the key is catastrophic because the repeated key cancels. An OTP also has no built-in integrity: an attacker may alter ciphertext even without learning the plaintext.

Key size and security Slide 15

  • Brute-force resistance: key length generally corresponds to symmetric security level, unless an algorithm flaw reduces that protection.
  • Comparison caution: security levels do not transfer directly between different algorithms. Triple DES has a 168-bit key but an attack complexity of $2^{112}$; 1024-bit RSA approximates 80-bit symmetric security.
  • Reference levels: 80-bit symmetric security is legacy; 128-bit is near-term protection; 256-bit is long-term protection.

Stream ciphers

A stream cipher generates a long keystream from a short key, acting like a reproducible pseudorandom number generator whose output can be used like an OTP pad. Encryption and decryption commonly use XOR with that stream.

Pseudorandomness Slide 23

True randomness Pseudorandomness
Uniformly distributed, independent bits. Approximately uniform output generated deterministically from a seed; its bits cannot be independent.

A pseudorandom keystream is not truly random, so a stream cipher does not offer perfect secrecy: not every possible keystream is possible.

Reuse and IV rules Slide 24 Slide 25

When $E(M_1) = M_1 \oplus C(K)$ and $E(M_2) = M_2 \oplus C(K)$, XORing the ciphertexts cancels the shared stream and reveals $M_1 \oplus M_2$. Frequency analysis and guessed words can then help recover the messages.

  • Initialization vector (IV): public extra input combined with a key to generate a different pseudorandom sequence for each message.
  • Requirement: an IV must be sufficiently large and never reused with the same key.
  • WEP example: WEP's 24-bit IV had about a 50% chance of reuse after roughly 5,000 packets, making RC4 attacks practical.

Confidentiality is not integrity Slide 28

Stream ciphers are malleable. When an attacker knows $M$ and $E(M)$, they can substitute a chosen $M'$ by transmitting:

E'(M) = E(M) \oplus M \oplus M' = C(K) \oplus M'

Bob decrypts the replacement as $M'$. A message authentication code (MAC) or authenticated encryption is needed to detect this manipulation.

Block ciphers

A block cipher is a keyed function that replaces a fixed-length input with a fixed-length output. For a fixed key, encryption is a bijection: a permutation of the block space, where each ciphertext block maps back to exactly one plaintext block.

Substitution, permutation, confusion, and diffusion Slide 32

  • Substitution: changes values and provides confusion, making the relationship between the key and ciphertext more complex.
  • Permutation: rearranges positions and provides diffusion, spreading the influence of each input bit across many output bits.
  • Modern construction: multiple rounds repeatedly apply keyed transformations while a key schedule derives round-specific subkeys.

DES, 3DES, and AES Slide 35

  • DES: obsolete and broken; its 56-bit key and 64-bit block size permit attacks including SWEET32-style collision risks.
  • 3DES: three applications of DES; it is deprecated.
  • AES: standardized in 2001; it uses 128-bit blocks and 128-, 192-, or 256-bit keys. It is the modern block cipher emphasized here.

AES internals: orientation only Slide 36

A 128-bit AES block is a $4 \times 4$ array of 8-bit bytes. Full rounds apply SubBytes, ShiftRows, MixColumns, and AddRoundKey; the final round omits MixColumns. The course goal is to recognize AES's construction and constraints, not to derive it by hand.

Arbitrary-length messages Slide 39

When a message does not fill a block, pad it with an established standard. Longer messages are split into blocks and processed using a block-cipher mode of operation.

Modes of operation

Modes define how a block cipher safely processes a message longer than one block. The lecture covers ECB, CBC, and CTR; all three are confidentiality-only modes.

Electronic Codebook (ECB) Slide 41

ECB encrypts each padded plaintext block independently with the same key. It supports parallel encryption, parallel decryption, and random access, but equal plaintext blocks produce equal ciphertext blocks. Do not use ECB for large or structured data because it leaks patterns.

Cipher Block Chaining (CBC) Slide 44

CBC XORs each plaintext block with the previous ciphertext block before encrypting it; the first block uses a random IV. It hides repeated patterns when used properly. Encryption is sequential, but decryption can be parallelized when ciphertext blocks are available.

CBC alone has no integrity. Modifying a previous ciphertext block causes predictable bit flips in the next decrypted plaintext block, so a MAC or authenticated-encryption mode is needed.

Counter mode (CTR) Slide 46

CTR encrypts unique counter values to generate a keystream, then XORs it with message blocks. It turns a block cipher into a stream-like cipher and supports parallel encryption, parallel decryption, and random access. Reusing a nonce/counter under the same key repeats the keystream and is catastrophic.

Choose authenticated encryption: when attackers can modify ciphertexts, prefer an approved AEAD construction such as CCM or GCM in a vetted protocol. Use confidentiality-only modes only when integrity and authenticity are provided elsewhere and all IV or nonce requirements are satisfied.
